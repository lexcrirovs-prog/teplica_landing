# Пакет публикации Premium E

Версия **2026.09.10.8 от 10.09.2026**. Исполнитель: **OpenAI Codex, GPT-6**.

Предлагаемый отдельный адрес: `https://prgz.ru/teplica8/`. Каталог размещения: `prgz.ru/public_html/teplica8`. Этот документ и сборщик не выполняют публикацию. Рабочие страницы `/teplica6/` и `/teplica7/` сохраняются.

## 1. Проверить исходники

Из корня проекта выполнить:

```powershell
node --test tests/*.test.cjs
node scripts/validate-page.cjs
node --check script.js
node --check scripts/build-release.cjs
```

Перед окончательной сборкой проверить актуальную версию в `version.json`, адреса canonical/Open Graph и источник заявки в `handler.php`. Они должны соответствовать одобренному адресу. Техническая успешность упаковки сама по себе не проверяет эти значения и не подтверждает работу PHP или почты.

## 2. Создать новый пакет

Требуется только Node.js 18 или новее. Дополнительные библиотеки, Python, PowerShell-архиватор и `tar` сборщику не нужны. ZIP использует стандартный метод STORE: фотографии уже сжаты в WebP. Содержимое ZIP воспроизводимо для одинаковых входных файлов; время сборки хранится отдельно в manifest.

Обязательный аргумент `--output-dir` задаёт **несуществующий каталог вне исходного проекта**. Его родительский каталог должен существовать. Пример из корня проекта, если каталог `../output` уже создан:

```powershell
node scripts/build-release.cjs --output-dir ../output/teplica8-2026.09.10.8-build01
```

Повторный запуск направлять в новый каталог, например `teplica8-2026.09.10.8-build02`. Сборщик не удаляет и не перезаписывает файлы. При ошибке неполный новый каталог остаётся для проверки; для следующей попытки также выбрать другой путь. Существующие архивы версии 2026.09.10.1 сохраняются.

Результат:

```text
teplica8-2026.09.10.8-build01/
  deployroot/                        Только содержимое будущего публичного каталога
  Premium-E-2026.09.10.8-deploy.zip    Те же файлы в корне ZIP
  release-manifest.json               Список файлов, размеры, SHA-256, версия и автор
  SHA256SUMS.txt                      SHA-256 архива
```

В `deployroot` и ZIP допускаются ровно семь файлов верхнего уровня: `index.html`, `styles.css`, `industrial.css`, `script.js`, `handler.php`, `.htaccess`, `version.json`, а также обычные изображения и шрифты из `assets/`. Символические ссылки и посторонние типы файлов внутри assets отклоняются. Вложенные каталоги assets сохраняются.

`docs/`, `tests/`, `scripts/`, `uploads/`, `.agents/`, Git, README и manifest не входят в публичный пакет. Ранее выданный **`Premium-E-2026.09.10.1.zip` является архивом исходников для передачи и хранения. Его нельзя целиком распаковывать в публичный каталог.**

Сборщик сверяет точный список staging-файлов, размеры и SHA-256 копий с исходниками, проверяет отсутствие изменений исходных файлов во время копирования, затем перечитывает ZIP. Для каждой ZIP-записи проверяются путь, размер, CRC-32, SHA-256, смещения и совпадение списка. Успешный результат обозначается `VERIFIED_LOCAL_PACKAGE`; `production_deployed` остаётся `false`.

Для независимой проверки архива в PowerShell:

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath ../output/teplica8-2026.09.10.8-build01/Premium-E-2026.09.10.8-deploy.zip
Get-Content -LiteralPath ../output/teplica8-2026.09.10.8-build01/SHA256SUMS.txt
```

Значения должны совпасть. Дополнительно можно открыть ZIP штатным архиватором и проверить, что `index.html` находится в корне, а исходные документы и служебные каталоги отсутствуют.

## 3. Публикация после одобрения

1. Перед загрузкой представить пользователю готовую версию, предлагаемый адрес, состав пакета и SHA-256 архива. Получить отдельное одобрение публикации.
2. Проверить, что новый путь `prgz.ru/public_html/teplica8` не содержит чужих или ранее опубликованных файлов. При занятом пути не перезаписывать его без отдельного решения.
3. Загрузить **только содержимое `deployroot/`** в новый каталог. Альтернатива: распаковать `-deploy.zip` в этот же каталог. Не создавать лишний уровень `deployroot` внутри публичного URL. Сохранить скрытый файл `.htaccess`.
4. Сверить загруженные пути, размеры и SHA-256 с `release-manifest.json`. Сам manifest, `SHA256SUMS.txt` и ZIP хранить вне публичного каталога.
5. Выполнить приёмку по HTTPS на новом адресе. Не менять и не перенаправлять `/teplica6/` и `/teplica7/` в рамках этой публикации.

## 4. Приёмка на сервере

На момент подготовки документа: **публикация не выполнена; PHP, почта и конфигурация Apache на `/teplica8/` не проверены**. Локальный просмотр не запускает PHP и не отправляет заявки.

После одобренной загрузки проверить главную страницу, canonical/Open Graph, версию, CSS/JS и все изображения; затем мобильную навигацию, расчёт и его ошибки, переключатели комплектации и сезона, печать и вариант без JavaScript. Проверить HTTP-заголовки, работу `.htaccess` и отсутствие публичных служебных файлов.

Обработчик должен исполняться как PHP, а не возвращаться исходным текстом. Read-only запрос к `handler.php` должен вернуть JSON с HTTP 405. Honeypot-проверка обрабатывается без письма и сама по себе не доказывает доставку почты. Полный тест заявки с отправкой письма выполняется в согласованном объёме; успех подтверждается получением письма с верным адресом источника и полями заявки. Ответ `mail()` не равен подтверждённой доставке.

Факт публикации и результаты приёмки фиксируются отдельной записью с датой, версией и контрольной суммой. Для отката отдельного адреса сохраняется точный размещённый пакет; отключение или удаление опубликованного каталога требует отдельного решения пользователя.
